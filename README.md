# web_security
渗透测试skills

# 实际架构：两条控制线

  ┌─────────────────────────────────────────────────────────────┐
  │ 控制线 A：CLAUDE.md（约束层，横向贯穿全程）                    │
  │  RoE授权分级 → Rate Limit ≤5 → Safe Payload → 报告格式       │
  │  「最高优先级，不可违反 / OVERRIDE」                           │
  └─────────────────────────────────────────────────────────────┘
                          ↓ 同时作用于每一步
  ┌─────────────────────────────────────────────────────────────┐
  │ 控制线 B：Skill 路由（攻击面决策层，纵向下钻）                 │
  │  P0  hack/SKILL.md   —— 核心路由表（现象→类别）+ 7条直觉       │
  │         ↓ 命中现象                                            │
  │  P1  api-sec / auth-sec / business-logic / recon... —— 分类路由│
  │         ↓ 二次观察                                            │
  │  P2  叶子技能（idor / sqli / ssrf / xss ...）—— 具体playbook   │
  └─────────────────────────────────────────────────────────────┘

  「先严格守 claude.md → 再按 hack/skill.md 路由」，两者「并行」：

  - CLAUDE.md 只做约束（能不能测、测多少次、payload 多无害、报告怎么写）。它是「宪法」。
  - hack/SKILL.md 做路由，做现象→类别→叶子技能的匹配决策。

# 执行顺序

  1. RoE 判定（第一步，硬门）——recon-for-sec/SKILL.md 开头就是「授权分级路由（RoE Gate，必须第一步执行）」，按 ROE 级别决定哪些章节可用。CLAUDE.md 也要求「开局先判授权级别并显式声明」。
  2. Recon / 现象观察——不是「先分析出漏洞」，而是先观察证据（响应头、报错、反射、路径）。
  3. 现象→路由——用 hack 路由表把「现象」匹配到 P1 类别（P0 层），P1 再匹配到 P2 叶子技能。
  4. 按需加载 + 逻辑卸载——hack 的「内存模式」规定：路由表和 7 条直觉长驻，叶子技能触发时才 read_file 加载，测完压缩成 1-2 句摘要卸载。
  5. 动态重路由——每轮测试后基于新发现重新对照路由表。

  所以准确的表述是：「现象驱动路由」，不是「漏洞类型驱动路由」。路由表的关键列是「现象」那一栏（如 ?file=report.pdf → Path Traversal），模型是拿观察到的现象去反查，而不是先断定「这是 IDOR」再去找技能。
